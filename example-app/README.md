# Пример первоначальной структуры для Bitrix (БУС) приложения

## 🚀 Быстрый старт

- ⬇️ Скачайте example-app (переименуйте раздел под ваш проект).
- 📄 Скопируйте `.env.exmample` в `.env` в корне проекта.

| Название переменной | Описание переменной                                                                                                                                                                                              | Требуется |
|:--------------------|:-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|:----------|
| APP_PATH            | Путь от корня до проекта внутри контейнера                                                                                                                                                                       | ✅         |
| APP_HOST            | Хост вашего приложения                                                                                                                                                                                           | ✅         |
| BUILD_BITRIX_VERSION | Редакция БУС: `start_encode` (по умолчанию), `standard_encode`, `small_business_encode`, `business_encode`. Любое другое значение — ошибка при старте контейнера                                                | ❌         |
| APP_DEBUG           | Вкл/выкл режим дебага для БУС (1 - вкл., 0 - выкл.)                                                                                                                                                              | ❌         |
| BITRIX_CRON_ENABLED | Вкл/выкл CRON (1 - вкл.; раз в минуту): `bitrix/php_interface/cron_events.php`. Допустимы только `0` или `1`                                                                                                     | ✅         |
| MAILPIT_ENABLED     | Вкл/выкл mailpit. Если задана — только `0` или `1`; любое другое значение — ошибка при старте контейнера                                                                                                         | ❌         |
| MAILPIT_HOST        | Хост mailpit. Обязательна, если `MAILPIT_ENABLED=1`                                                                                                                                                              | ❌         |
| PHP_IDE_CONFIG      | Спец. переменная для Xdebug (без этой переменной работать не будет)                                                                                                                                              | ❌         |
| DB_USER             | Имя пользователя для базы данных (используется для СУБД)                                                                                                                                                         | ✅         |
| DB_PASSWORD         | Пароль пользователя для базы данных (используется для СУБД)                                                                                                                                                      | ✅         |
| DB_ROOT_PASSWORD    | Секретный пароль пользователя для базы данных (используется для СУБД)                                                                                                                                            | ✅         |
| DB_DATABASE         | Название базы данных (используется для СУБД)                                                                                                                                                                     | ✅         |
| DB_HOST             | Хост базы данных (хостом БД является название контейнера СУБД из docker-compose.yml; используется для СУБД)                                                                                                      | ✅         |

👇 Пример `.env` файла:

```
APP_PATH=/pub/www/app  
APP_HOST=app.local
BUILD_BITRIX_VERSION=start_encode
  
DB_USER=db_user
DB_PASSWORD=db_password
DB_DATABASE=sitemanager
DB_ROOT_PASSWORD=secret
DB_HOST=database
  
APP_DEBUG=1
BITRIX_CRON_ENABLED=0
```

- 📄 Создайте в корне проекта файл `bx.cnf`, который настраивает СУБД `MySQL` для максимально эффективной работы.

```
[mysqld]  
  
# STRICT_TRANS_TABLES — строгий режим для транзакционных таблиц:  
# Запрещает вставку невалидных данных (например, строку в числовое поле)  
# Прерывает INSERT/UPDATE при ошибках вместо молчаливого усечения  
# Защищает от потери данных  
  
# NO_ENGINE_SUBSTITUTION — запрещает автоматическую замену движков:  
# Если указан несуществующий движок таблицы (например, ENGINE=MyISAM при его отключении)  
# Выдает ошибку вместо автоматической замены на движок по умолчанию  
  
sql_mode=NO_ENGINE_SUBSTITUTION,STRICT_TRANS_TABLES  
  
# Полноценная поддержка UTF-8 (4 байта на символ)  
# Поддерживает все символы Unicode, включая эмодзи, иероглифы и специальные символы  
# В отличие от utf8 (который в MySQL только 3-байтовый)  
  
character-set-server=utf8mb4  
  
# Регистронезависимое сравнение для utf8mb4  
# Правильная сортировка многоязычных данных  
# Поддерживает специфичные правила для разных языков  
  
collation-server=utf8mb4_unicode_ci  
  
# Часовой пояс Москвы с учетом летнего времени  
# Автоматически переходит на зимнее/летнее время  
# Лучше чем +03:00, так как учитывает исторические изменения  
  
default-time-zone=Europe/Moscow  
  
# Увеличенный лимит до 256 МБ  
# Для работы с большими BLOB, медиафайлами, длинными текстами  
# Необходимо для импорта/экспорта больших баз данных  
  
max_allowed_packet = 256M  
  
# Размер кэша InnoDB — 1 гигабайт  
# Хранит в RAM: индексы, данные, адаптивные хэши  
# Критически важный параметр для производительности  
# Обычно устанавливают 50-80% от доступной RAM  
  
innodb_buffer_pool_size = 1G  
  
# Размер файлов журнала транзакций — 256 МБ  
# Большие значения уменьшают частоту checkpoint'ов  
# Улучшает производительность при интенсивной записи  
# Требует перезапуска MySQL для изменения  
  
innodb_log_file_size = 256M
```

- 📄 Создайте в корне проекта файл `docker-compose.yml`, который описывает настройки запуска вашего приложения.

👇 Пример `docker-compose.yml` файла с использованием **MySQL** в качестве СУБД нашего приложения. В поле `image` для
`application` укажите нужный тег образа, например `php-8.3-fpm-bookworm` или `php-8.5-fpm-trixie`:

```yml
services:

  application:
    image: armhaina/bitrix:php-8.3-fpm-bookworm
    working_dir: ${APP_PATH}
    env_file: .env
    environment:
      PHP_IDE_CONFIG: serverName=${APP_HOST}
    extra_hosts:
      - "host.docker.internal:host-gateway"
    stdin_open: true
    tty: true
    ports:
      - "80:80"
    volumes:
      - ./app:${APP_PATH}:cached
    depends_on:
      - database

  database:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: ${DB_ROOT_PASSWORD}
      MYSQL_DATABASE: ${DB_DATABASE}
      MYSQL_USER: ${DB_USER}
      MYSQL_PASSWORD: ${DB_PASSWORD}
    ports:
      - "3306:3306"
    volumes:
      - ./bx.cnf:/etc/mysql/conf.d/bx.cnf
```

- 📄 Запустите сборку проекта командой из корня проекта. Редакция БУС берётся из `BUILD_BITRIX_VERSION` в `.env` (если не указана — `start_encode`).

```bash
docker compose up -d --build --remove-orphans
```

В логах контейнера `application` вам будет доступен процесс создания проекта. Завершением сборки можно считать появление
зелёной строки `✅ КОНТЕЙНЕР ГОТОВ — ЗАПУСКАЮ NGINX И PHP-FPM`.

😎 Если сборка проекта успешно завершена, то можете перейти на страницу `http://localhost` или `http://APP_HOST` (заменить **APP_HOST** на хост из `.env` файла). Вы должны увидеть стартовую страницу установки `БУС`.

1. На странице `Предварительная проверка` все обязательные параметры и доступы к диску должны быть выделены зеленым
   цветом.
2. На странице `Создание базы данных` указать следующие данные: `Сервер` (название вашего контейнера СУБД; значение из
   переменной DB_HOST), `Имя пользователя` (значение из переменной DB_USER), `Пароль` (значение из переменной
   DB_PASSWORD), `Имя базы данных` (значение из переменной DB_DATABASE). Больше ничего менять не надо.
3. На странице `Выберите решение для установки` выберите любой из готовых шаблонов (рекомендуется НЕ использовать
   `Загрузить из Маркетплейс`, так как эти шаблоны от сторонних разработчиков и могут содержать ошибки).
4. После установки БУС вы попадете на главную страницу вашего сайта с предустановленным шаблоном. Для перехода в
   админ-панель БУС перейдите на страницу `http://localhost/bitrix` или `http://APP_HOST/bitrix`
5. 🔥**БУС** успешно установлен!

## 🛠️ Доп. настройки

### ⚙️ Проставить переменные .env в конфиги

👇 Следующие значения в файле `/bitrix/.settings.php` заменить:

```php
[  
  'debug' => (bool)$_ENV["APP_DEBUG"], # если указывали APP_DEBUG в .env   
];
```

```php
[  
  'host' => $_ENV["DB_HOST"],  
  'database' => $_ENV["DB_DATABASE"],  
  'login' => $_ENV["DB_USER"],  
  'password' => $_ENV["DB_PASSWORD"],  
];
```

👇 Следующие значения в файле`/bitrix/php_interface/dbconn.php`заменить:

```php
$DBDebug = (bool)$_ENV["APP_DEBUG"];  
$DBDebugToFile = (bool)$_ENV["APP_DEBUG"];
```
